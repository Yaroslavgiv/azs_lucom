# Технический проект по ТЗ 1.3

Основание: «Техническое задание. Развитие системы обслуживания АЗС», версия 1.3 от 27.09.2026. Ниже контракты, по которым написан код.

## Роли

Три роли: специалист, руководитель, администратор. Подробности и совместимость старых кодов — в [roles.md](roles.md).

## Заявка

Исполнитель копируется из `stations.specialist_id` в момент создания. Срок считается от времени создания плюс `duration_hours` действующего `contract_rules` по категории. Если правила нет или длительность не задана, `due_at` остаётся пустым.

| Из | Действие | Кто | В |
| --- | --- | --- | --- |
| `unassigned` | отменить | руководитель области | `cancelled` |
| `created` / `assigned` | начать | специалист станции | `in_progress` |
| `created` / `assigned` / `in_progress` / `returned` | завершить | специалист станции | `closed`, если проверка не требуется |
| `in_progress` / `returned` | на проверку | специалист станции | `on_review` |
| `on_review` | принять | руководитель | `accepted` |
| `on_review` | вернуть | руководитель, комментарий обязателен | `returned` |
| `created` / `unassigned` | отменить | руководитель | `cancelled` |

Ручное назначение отклоняется. Повтор той же команды не создаёт второе событие аудита. Для прежних отчётов `accepted`, `closed` и `cancelled` пишутся в `requests.status` как `closed`.

## Ежемесячное ТО

На текущий месяц Москвы (`Europe/Moscow`, UTC+3) для активной станции создаётся одна запись `not_done`. Специалист фиксирует выполнение действием `complete`: статус `done`, дата и время в `date_done`. Повторная фиксация того же месяца ничего не меняет.

Невыполненные месяцы раньше текущего закрываются как `overdue`. Это не действие пользователя. Новый месяц снова начинается с «не выполнено», история прошлых месяцев сохраняется. Чек-лист, фото и приёмка руководителя в сценарии ТО не используются.

## Карта

Цвет только на маркере, без текста статуса:

1. Красный — просроченное ТО прошлого периода или просроченная/критическая договорная заявка. Красный важнее зелёного.
2. Зелёный — ТО текущего месяца зафиксировано и красного условия нет.
3. Жёлтый — ТО текущего месяца не зафиксировано.

Легенда на экране карты поясняет эти три цвета.

## Договорные правила

Таблица `contract_rules`: категория, длительность в часах, признак проверки, дата начала действия, версия, активность. Смена правила не требует выпуска приложения. Пока заказчик не передал длительности, срок не подставляется.

## Очередь и файлы

Очередь хранит попытки, ошибку, состояние, ключ идемпотентности и `depends_on`. После пяти неудач операция остаётся в `error`. Команды статуса применяет Cloud Function `applyWorkCommand`. Вложения и Firebase Storage не входят в пользовательский сценарий версии 1.3.

## Создание АЗС

Право есть у руководителя и администратора. Адрес геокодируется через DaData и показывается до сохранения. Пустой ответ геокодера не ставит точку. Дубль — совпадение номера, нормализованного адреса или расстояние не больше 50 метров.

Серийный номер оборудования необязателен.

## Отчёты

Книги `заявки.xlsx`, `ТО.xlsx`, `оборудование.xlsx` и заказы оборудования сохраняют прежние имена и колонки. Книга `отчёт_выборки.xlsx` повторяет фильтр панели.

## Смена Firebase

Клиенты ходят в данные через репозитории и `SyncService`, а не через форму коллекций из UI. Порядок выгрузки и переноса описан в [firebase-migration.md](firebase-migration.md). Сам перенос в другой backend в эту версию не входит.
