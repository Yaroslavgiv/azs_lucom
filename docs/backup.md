# Резервное копирование и восстановление

Прикладные данные лежат в Cloud Firestore проекта. Пользовательские вложения в версии 1.3 не хранятся.

## Регламент проверки

1. Экспортировать Firestore в отдельный тестовый проект.
2. Выбрать станцию, заявку текущего месяца и запись ТО.
3. Восстановить экспорт в пустую базу.
4. Сверить номер станции, исполнителя заявки и статус ТО.
5. Зафиксировать дату проверки в журнале эксплуатации.

Численные RPO и RTO утверждает заказчик. Экспорт выполняется перед пилотом и перед промышленным включением. Service account JSON в репозиторий не помещается.

Журналы Cloud Functions пишут корреляционный идентификатор и проходят через `redactLog`: пароли, токены и JWT в текст не попадают.

Порядок смены самого backend описан в [firebase-migration.md](firebase-migration.md).
