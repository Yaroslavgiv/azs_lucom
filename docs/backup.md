# Резервное копирование и восстановление

Прикладные данные лежат в Cloud Firestore проекта, файлы — в Firebase Storage по пути `attachments/{entityType}/{entityId}/{fileName}`.

## Регламент проверки

1. Экспортировать Firestore и бакет Storage в отдельный тестовый проект.
2. Выбрать заявку с вложением в состоянии `uploaded`.
3. Восстановить экспорт в пустую базу.
4. Открыть заявку и убедиться, что метаданные вложения ссылаются на существующий объект Storage.
5. Зафиксировать дату проверки в журнале эксплуатации.

Численные RPO и RTO утверждает заказчик. До этого экспорт выполняется перед пилотом и перед промышленным включением. Service account JSON в репозиторий не помещается.

Журналы Cloud Functions пишут корреляционный идентификатор и проходят через `redactLog`: пароли, токены и JWT в текст не попадают.
